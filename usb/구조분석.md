# 의성에서, 살다: USB 실행 구조

## 기존 프로젝트

HTML·CSS·JavaScript ES modules로 구성된 정적 웹서비스이며 React/Next.js 등 서버 프레임워크는 없습니다.
Node.js는 개발·빌드·테스트 도구이며 웹 화면 실행에 필수인 서버 런타임이 아닙니다.
기존 `npm run build`는 USB용 `index.html`과 Vercel용 `public/index.html`을 생성합니다.
기존 Git origin과 `vercel.json`을 변경하지 않았습니다.

## USB 빌드

`npm run build:usb`는 같은 `src/page.html`, `src/style.css`, `src/app.js`, `src/data.js`를 사용해
`usb-submission/dist`를 만듭니다. 기존 디자인·18개 읍면·네 분야·맞춤 검색·관심 저장·상세보기를 유지합니다.
추가된 부분은 로컬 CSV 로더와 데이터 로딩 상태 안내뿐이며 파일 업로드 영역은 없습니다.
외부 Google Fonts는 번들에 포함하지 않고 시스템 글꼴로 대체합니다.

USB에서 읽는 `dist/data/records.csv`는 전체 432건을 담은 UTF-8 BOM 파일입니다.
CSV의 텍스트는 HTML 출력 시 이스케이프하며 공식 링크는 HTTPS만 사용합니다.
월세·보증금 단위는 만 원, 시급 단위는 원입니다. 없는 금액은 ‘정보 없음’으로 표시합니다.
동일 자료의 `records.json`은 검토용 사본이며 실행 시 데이터 원본은 CSV입니다.
CSV를 읽지 못하면 내장 가상자료를 사용하고 안내하므로 메인 화면을 계속 볼 수 있습니다.

## 로컬 서버와 시작

Go 표준 라이브러리만 사용한 정적 서버를 Windows x64·ARM64·x86용 EXE로 크로스컴파일합니다.
대상 PC에서 Go·Node.js·Python·npm이나 패키지 설치가 필요하지 않습니다.
빌드에 사용한 공식 Go 툴체인은 공식 배포 체크섬으로 검증했습니다.
서버 소스는 `source/usb/server`에 포함됩니다.

`실행하기.bat`는 `%~dp0`로 자신의 위치를 계산하고 인용된 상대 경로의 서버와 dist를 사용합니다.
Windows 드라이브 문자를 고정하지 않고, 현재 명령 프롬프트 디렉터리에 의존하지 않습니다.
서버는 127.0.0.1에만 바인딩하며 외부 LAN 접속이나 쓰기 API를 제공하지 않습니다.
준비 상태 응답을 확인한 뒤 기본 브라우저를 호출합니다.
기본 포트는 18765이며 충돌 시 30개 포트를 순서대로 시도합니다.
동일한 콘텐츠의 서버가 이미 실행 중이면 기존 서버를 재사용합니다.
정적 파일 경로는 dist 안으로 제한하며 폴더 목록·숨김파일·다른 디렉터리 파일은 제공하지 않습니다.
콘솔 외에 USB에 실행 로그를 쓰지 않으므로 일반 실행 시 쓰기 권한이 필요하지 않습니다.

## 오프라인 범위

화면·CSV 필터·맞춤 검색·상세·관심 정보는 로컬 처리합니다.
외부 API·비밀키·폰트 다운로드·CDN·로그인·클라우드 DB에 의존하지 않습니다.
외부 공식 사이트 링크는 명시적으로 클릭할 때만 인터넷을 사용합니다.
브라우저의 관심 정보는 해당 PC의 localStorage에 남으며 USB 데이터 파일에는 쓰지 않습니다.

## 개발과 재생성

이 폴더는 심사용 실행물입니다. 일반 실행에는 아래 도구가 필요하지 않습니다.
개발 재빌드 시 Node.js 18 이상, Python 3, Go 1.24 이상이 필요합니다.
원본 코드 폴더에서 `npm run build:usb`를 실행하고,
`python3 scripts/package-windows-usb.py --go /사용할/Go/실행파일`로 EXE와 최종 ZIP을 만듭니다.
Go 외부 모듈은 사용하지 않으며 `CGO_ENABLED=0`, `-trimpath`, `-buildvcs=false`로 빌드합니다.
